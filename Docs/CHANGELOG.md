# HearIt Changelog

All notable changes to HearIt are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Full documentation set: phase plan, architecture, global standards, technical decisions (ADRs), manual test checklist.
- Eligibility rules part 2 (P02): text-length limits (per message / whole notification, skip-never-truncate), case-insensitive whole-word/phrase keyword filtering (off by default), and privacy rules (exclude app, OTP, password, payment, banking, custom sensitive keywords, hide-content flag for P04) with ADR-006 precedence and Priority Announce unable to bypass them. JVM unit tests written — not yet executed (cloud-agent restriction).
- Eligibility rules part 3 (P03): active-call suppression (per-app call-time queueing, off by default, returning a new `Queue(CALL_ACTIVE)` decision that must be re-evaluated through the full pipeline), DND respect with global/per-app override that reads only the device flag, and allowed-audio-output matching (wired/Bluetooth on, phone speaker off, unidentified outputs allowed, per-device Bluetooth allow-list, unobserved output allowed). New reasons `CALL_ACTIVE`, `DND`, `OUTPUT_NOT_ALLOWED`; silent-channel metadata added to snapshots to keep channel policy distinct from DND (ADR-017). JVM unit tests written — not yet executed (cloud-agent restriction).
- Announcement format and TTS contract (P04): pure announcement-template builder producing typed sections (introduction, app name, sender, message) that reproduces the master-prompt default "WhatsApp. Rahul says, …" exactly, omits missing content without dangling connectors, and carries a configurable pause between sections; `SpeechSettings` for speed/pitch/voice (defaults 1.0/1.0/engine default). New `:core:tts` Kotlin/JVM module with the `TextToSpeechEngine` contract (availability, voices, locale support, utterance lifecycle, stable error codes) for the Android wrapper to satisfy. JVM unit tests written — not yet executed (cloud-agent restriction).
- Queue, grouping and scheduling (P05): new `:core:queue` Kotlin/JVM single-writer state machine covering priority ordering (Critical/High/Normal/Low first, equal FIFO), same-app grouping window with per-app override and message cap, announcement delay and minimum gap, never-interrupt while speaking, global/per-app size limits with all three overflow policies, expiry for pending and call-held items, dedup of updates to already-announced notifications (pending same-key updates replace in place), and call-hold storage with FIFO release for full-pipeline re-evaluation. Every removal carries history status + reason (`EXPIRED`, `OVERFLOW`, `DUPLICATE_UPDATE` added to `SkipReason`; `HistoryStatus` introduced); injected `Clock` in `:core:common`; grouped-announcement template build (app name + "N messages." + content, §8). JVM unit tests written — not yet executed (cloud-agent restriction).
- Build foundation (P06): Hilt 2.60.1 + KSP 2.3.13 wired through the version catalog (root `apply false`; `ksp`/`hilt` plugins in `:app`; `hilt-android` implementation + `hilt-compiler` via `ksp`; no kapt, no legacy kotlin-android plugin under AGP 9 built-in Kotlin), `HearItApplication` (`@HiltAndroidApp`) registered in the manifest, `@AndroidEntryPoint MainActivity`. Manifest baseline reviewed for API 29–37: explicit `exported` flags, notification-listener service slot (signature `BIND_NOTIFICATION_LISTENER_SERVICE`, class lands in P07), announcement-service slot with `foregroundServiceType="mediaPlayback"` (class lands in P08), only install-time normal FGS permissions declared now — dangerous permissions (`POST_NOTIFICATIONS`, `BLUETOOTH_CONNECT`) deferred until their setup flow explains them. No unit-testable logic added, so no tests written; build and tests not run (cloud-agent restriction).
- Notification listener foundation (P07): new `:core:notifications` Android library with `HearItNotificationListenerService` (binding lifecycle with a single guarded rebind after disconnect/permission loss, own notifications never forwarded, no content in logs), a thin `StatusBarNotification` → `RawNotification` mapping layer, and pure JVM-tested extraction: stable `package|tag|id` keys, bounded update-vs-new detection, trimmed title/bigText/text with blank-to-null fallbacks, sender suppressed when it merely repeats the app name, missing title/text/extras handled, post-time fallback, channel/category passthrough. Snapshots are delivered through the `NotificationSink` contract for the P08 pipeline (no speech or rules logic in the listener). JVM unit tests written — not yet executed (cloud-agent restriction).
- Foreground announcement service and speech pipeline (P08): `AnnouncementService` (foreground `mediaPlayback`, explicit start/stop only, `SessionStore` start flag so system recreation never auto-announces, persistent notification with Stop and static service text only, tick loop with stop-on-change checks, audio-device-removal stop) plus the pure `AnnouncementPipeline` (rules → queue → speech action, call-held release re-evaluated through the full pipeline, empty groups retired silently, stop reasons for eligibility loss/silence/output loss), `AndroidTextToSpeechEngine` satisfying the P04 contract section by section with INTERRUPTED/terminal-callback discipline, `RuntimeStateReader` (screen/lock/DND/call-proxy/output, no permissions), `SettingsSource` placeholder (all apps disabled until P09/P13), `SpeechModule` Hilt wiring and the `NotificationRelay` bridge from the listener. Also fixed a P07 defect: `:core:queue` no longer imports `android.media.AudioManager` (impossible in a pure JVM module) — the silence gate is now the pure `DeviceAudioState` interface, with the Android adapter in the service. JVM unit tests written — not yet executed (cloud-agent restriction).
- ADR revisions (2026-10-31, on user direction): ADR-006 accepted with precedence regrouped as device states (mute/call/DND) before content rules and keyword before length; ADR-015 accepted with v1 defaults OTP+password skip on, financial skips off, no text-length limit. Code, tests and KDoc updated to match.
- `:core:common` and `:core:rules` Kotlin/JVM modules (P01): notification snapshot, eligibility settings with per-app inheritance, runtime state, skip reasons, and the deterministic announcement-eligibility pipeline covering the enabled-app list, temporary mute and screen/lock with the Priority Announce override. JVM unit tests written for all three rule families — not yet executed (cloud-agent restriction).
