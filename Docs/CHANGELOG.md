# HearIt Changelog

All notable changes to HearIt are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- App Security & Privacy additions (Master prompt §15): Implemented optional Biometric & Device Credential authentication gate and Secure Screen mode (`FLAG_SECURE`). Added `SecuritySettings` domain model to `:core:common`, serialized via `SettingsCodec` (`security.biometricLock` and `security.secureScreen`). Created `BiometricAuthManager` using Android platform's `BiometricPrompt` supporting biometric and device credential (PIN/pattern/password) fallback. Added a dedicated "Security & Device Privacy" section to General Settings with interactive switches. Configured dynamic `FLAG_SECURE` in `MainActivity` to shield notification previews in the Android task switcher (Recents) and prevent screenshots. Created Material 3 Expressive `AppLockScreen` overlay auto-locking upon app backgrounding (`ON_STOP`) and prompting for biometric authentication upon resume, with the background announcement service continuing speech synthesis without interruption when the UI is locked.
- Structured Diagnostic File Logging & Export (Master prompt §17): Added a file-based rotating logger (`FileDiagnosticLogger`) adhering to a strict privacy invariant (metadata only, guaranteed zero notification text/OTPs). Implemented automatic 7-day circular retention, thread-safe asynchronous file appends, and structured log categories (`NOTIFICATION`, `RULES`, `QUEUE`, `AUDIO`, `TTS`, `SERVICE`). Integrated across `HearItNotificationListenerService`, `AnnouncementPipeline`, and `AnnouncementService`. Added a dedicated M3 section card to the Diagnostics screen with live file counts/sizes, a SAF `CreateDocument` Export button producing formatted diagnostic `.txt` reports, and a confirmed Clear Logs action.
- Persistent Service Notification management (Notification Panel Control): Added a dedicated "Service Notification" settings card to General Settings with real-time status detection ("Visible in Panel" vs "Hidden from Panel"), an interactive switch with confirmation guidance, and a direct "Configure in Android Settings" action button navigating directly to `Settings.ACTION_CHANNEL_NOTIFICATION_SETTINGS`. Foreground service channel configured with `NotificationChannel.setBlockable(true)` (API 28+) so users can completely hide the persistent "Hear It is running" notification from the Android notification panel/shade without affecting foreground service execution or announcement speech synthesis.
- Modern Material 3 Expressive Global Rules screen: Hero status card with active policy badges, interactive device state segments (Screen Off/On/Either, Lock/Unlock/Either) with recommendation chips, quick text-length chips with custom character limit inputs, interactive keyword tag cloud with inline add/delete, Privacy and Content Shields with dedicated icons and descriptive subtitles (OTP, Passwords, Banking, Payments, Hide Content, Exclude from Logs), and Allowed Audio Outputs with phone speaker warning.
- Diagnostics screen (P19): Real-time system diagnostics featuring hero health status, Announcement Service daemon monitor (running/speaking/queue/priority mode), Permissions probe (Notification access, Post Notification, Nearby Bluetooth devices, Unrestricted battery optimization shortcut), Text-to-Speech readiness with asynchronous initialization polling, connected audio output hardware routing, and room database/enabled apps storage health.
- Backup & Restore settings screen (P19): Settings-only JSON export and import using Android Storage Access Framework (SAF) contracts (`CreateDocument`/`OpenDocument`), version/schema validation, raw JSON configuration clipboard copy, and manual JSON editor.
- General Settings screen (P15): Audio focus selector (`DUCK`, `PAUSE`, `NONE`), notification grouping window and message caps, delivery delay buffer and minimum gap cooldowns, queue capacity limits with eviction policies (`DISCARD_OLDEST`, `DISCARD_NEWEST`, `KEEP_HIGHEST_PRIORITY`), and notification update re-announcement controls.
- Voice & Speech settings screen (P15): Interactive dynamic speech preview bubble, live audio test player via `TextToSpeechEngine` with async availability polling, speech speed/pitch sliders (`0.5x`–`2.0x`) with quick presets, system installed voice picker dialog, announcement format switches, custom introduction text field, and section pause selectors.
- Dashboard quick controls enhancements: Aligned Temporary Mute card layout with Priority Announce, added custom mute duration dialog (5m, 15m, 30m, 1h, custom minutes), disabled quick controls when service is stopped, and implemented temporary mute suspension with automatic priority state resumption upon unmute.
- Full documentation set: phase plan, architecture, global standards, technical decisions (ADRs), manual test checklist.
- Eligibility rules part 2 (P02): text-length limits (per message / whole notification, skip-never-truncate), case-insensitive whole-word/phrase keyword filtering (off by default), and privacy rules (exclude app, OTP, password, payment, banking, custom sensitive keywords, hide-content flag for P04) with ADR-006 precedence and Priority Announce unable to bypass them. JVM unit tests written — not yet executed (cloud-agent restriction).
- Eligibility rules part 3 (P03): active-call suppression (per-app call-time queueing, off by default, returning a new `Queue(CALL_ACTIVE)` decision that must be re-evaluated through the full pipeline), DND respect with global/per-app override that reads only the device flag, and allowed-audio-output matching (wired/Bluetooth on, phone speaker off, unidentified outputs allowed, per-device Bluetooth allow-list, unobserved output allowed). New reasons `CALL_ACTIVE`, `DND`, `OUTPUT_NOT_ALLOWED`; silent-channel metadata added to snapshots to keep channel policy distinct from DND (ADR-017). JVM unit tests written — not yet executed (cloud-agent restriction).

Every removal carries history status + reason (`EXPIRED`, `OVERFLOW`, `DUPLICATE_UPDATE` added to `SkipReason`; `HistoryStatus` introduced); injected `Clock` in `:core:common`; grouped-announcement template build (app name + "N messages." + content, §8). ### Changed
- Devices feature (phase L5): the Devices tab is no longer a placeholder — allowed output types
  (Bluetooth, wired, phone speaker, unrecognised), a per-device Bluetooth allow-list with an
  explicit warning when every device is unchecked, a remembered device list with connection state
  and Forget, and a rescan action. New `KnownAudioDevice` + `HearItSettings.knownDevices` persist the
  remembered outputs under `devices.known` (no schema bump or migration), and every decision is
  written through `SettingsRepository` so the rules enforce exactly what the screen shows. Per-device
  selection remains Bluetooth-only because wired and speaker are category settings.
- History feature (phase L4): the History tab is no longer a placeholder — search across app name,
  sender and stored message text, a status filter, newest/oldest/by-app sorting, paged loading
  (50 rows per page), per-entry delete and clear-all behind confirmation dialogs, and global
  storage-mode, update-handling and retention controls. New `HistoryQuery.searchText`
  (case-insensitive `LIKE`, no schema change or migration) backs the search, and the dashboard's
  history search uses the same field. The UI is compile-verified only and has no per-app or
  date-range filter yet.
- History recording (phase L3): the announcement pipeline now reports every outcome to a history
  sink, and `AnnouncementService` persists it through `HistoryRepository` (single ordered consumer,
  app-specific storage mode and update handling, retention sweep after a settings change). Skips,
  queued items, announced items, expiries, overflow discards and deduplicated updates all reach
  history, so the dashboard's recent-history section and its search/clear actions now have data.
- Settings wiring (phase L2): `AnnouncementService` now reads the persisted settings through a
  `SettingsRepository`-backed `SettingsSource` (a snapshot mirrored from the repository flow for the
  service's lifetime), so enabling an app in Applications actually reaches the eligibility rules.
  Per-app priority, Priority Announce listings (now persisted rather than in-memory), the
  announcement format, speech speed/pitch/voice and the queue's grouping/size/delay/gap values all
  come from the user's stored settings; the queue is reconfigured once per settings emission.
- First local build (phase L1): the project now compiles. Five Kotlin/JVM modules had their Java/Kotlin targets aligned, `:core:database` gained its Room schema input directory, `:app` gained the Room runtime dependency, and the Quick Settings tile was rebuilt against the real `TileService`/`Tile` API (correct `BIND_QUICK_SETTINGS_TILE` permission, `QS_TILE` action, `TOGGLEABLE_TILE` metadata; the unsupported tile layout/config resources were removed).
- Rewritten because they never compiled: dashboard models/ViewModel/screen, the Global Rules screen (now backed by a real `GlobalSettingsViewModel` writing through `SettingsRepository`), the global settings UI state, `SettingsSource` (apps stay disabled by default; Priority listing separate), and the history DAO sort (enum names instead of enum constants in `@Query`).
- Announcement history now records `ANNOUNCED` via the new `QueueEvent.Announced`, and the lock skip reason names the actual device state.

### Fixed
- Announcements held because a call was in progress are now spoken once the call ends (phase L6):
  `AnnouncementService` releases them on the next tick through the full pipeline, so screen, lock,
  mute, DND and output are re-checked and nothing is spoken on the strength of its held-time decision.
  Previously `AnnouncementPipeline.releaseHeld` was never called and held items simply expired, so the
  "announce after a call" setting did nothing.
- The stored audio-focus policy is now applied while speaking (phase L6): transient focus is requested
  with ducking (`DUCK`, the default) or without (`PAUSE`), `NONE` requests nothing, focus is abandoned
  whenever the utterance ends, and losing focus to another app or a call stops the announcement. The
  setting was previously resolved but never acted on.
- History no longer records `ANNOUNCED` for speech that never completed: a stop, skip, engine error
  or rejected utterance is stored as `INTERRUPTED`, and a group retired because every announcement
  section was empty is stored as `SKIPPED`.
- `strings.xml` was invalid XML (literal `\n` escapes, `unicode_escape` encoding, raw `&`, seven duplicate string names); `AndroidManifest.xml` had an unclosed `meta-data` element and a non-existent Quick Settings permission.
- Settings backup import now converts the exported JSON object back into the codec's string map instead of passing a `JSONObject` where a `Map<String, String>` was required.
